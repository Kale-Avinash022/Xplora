## 1. What Is Xplora?

**Xplora** is a full-stack, AI-powered travel planning platform built on **Next.js 14 App Router**.

In plain terms: a user types a casual sentence like *"Plan a 5-day trip to Goa for 2 people on a ₹40,000 budget, I love beaches and adventure"* — and Xplora does everything else. It understands the request, asks clarifying questions if details are missing, generates a complete day-by-day itinerary, scores activities mathematically, searches live flights and hotels, monitors the weather, and even swaps outdoor activities to indoor ones if rain is forecast. The finished itinerary can be exported as a PDF, synced to Google Calendar, or saved for later.

**Type:** Full-stack web application (SPA with server-side API routes)  
**Stack:** Next.js 14, TypeScript, Prisma ORM, SQLite, Tailwind CSS  
**Primary Language:** TypeScript  
**Status:** All 8 phases complete — production-ready

## 2. What Problem Does It Solve?

| Pain Point (Before Xplora) | How Xplora Fixes It |
| :--- | :--- |
| Planning a trip requires visiting 10+ websites (flights, hotels, weather, maps) | Single unified platform — search, plan, and book from one place |
| Generic AI chatbots give vague, unstructured travel suggestions | Structured NLP extraction → editable confirmation → scored itinerary output |
| Outdoor plans get ruined by unexpected rain | Automated weather monitoring auto-swaps outdoor activities with indoor alternatives |
| Activities are clustered poorly, causing long commutes between spots | Spatial nearest-neighbor algorithm groups daily stops by geographic proximity |
| No way to export or share trip plans | 1-click PDF export, Google Calendar sync, and `.ics` file download |
| Trip budgets spiral out of control | Built-in multi-currency expense tracker with real-time conversion |

## 3. What Xplora Achieves — Feature Highlights

### 🤖 Natural Language Intent Parsing
Users speak freely. Xplora's `/api/parse-query` endpoint uses an NLP engine to extract structured entities:
`destination` · `startDate` · `durationDays` · `budget` · `numTravelers` · `interests` · `missingFields`

If fields are missing, it enters a **Clarifying Question Loop** — asking *"Which destination would you like to explore?"* — until the prompt is complete.

---

### 📋 User-in-the-Loop Verification (Screen 2)
Before any itinerary is generated, the parsed details appear in an **editable confirmation modal** (`ConfirmParsedDetailsModal.tsx`). The user can correct anything the AI misunderstood — destination city, dates, budget, traveler count, interest tags — then click **"🚀 Confirm & Generate Itinerary ➔"**.

---

### 🧮 Mathematical Recommendation Scoring
Every hotel, flight, and activity gets a score using a weighted formula:

```
Score = 0.4 × Rating  +  0.3 × PriceFit  +  0.3 × InterestMatch
```

- **Rating** — normalized star/review rating
- **PriceFit** — how well the price fits within the user's budget
- **InterestMatch** — how well the option matches user's declared interests (Beach, Adventure, Heritage, etc.)

This produces scores like `92/100` that are surfaced to the user.

---

### 📍 Spatial Nearest-Neighbor Clustering
Activities for each day are grouped by geographic proximity. The algorithm picks the next activity that is closest to the current location, minimizing travel time and creating logical sightseeing routes — no more zigzagging across a city.

---

### ☔ Weather-Swap Safeguard
Live weather forecasts are checked for every trip day. If precipitation probability exceeds 50%:
- Outdoor activities (beach, hiking, nature) → automatically replaced with indoor alternatives (museums, spas, cooking classes, indoor dining)
- A `WeatherSwapBanner` is shown on the itinerary screen explaining which swaps were made

---

### ✈️ 25+ Flights & 35+ Hotels Catalog
Live search integrations with:
- **SerpAPI** (Google Flights + Google Hotels)
- **Aviationstack API** (flight data)
- **RapidAPI / TripAdvisor** (hotel data)

Filters: non-stop flights, time-of-day slots, near-beach/near-airport hotels, price ranges, star ratings.

---

### 💰 Financial Suite
- **Multi-currency converter**: INR ₹ · USD $ · EUR € · GBP £ · AED · JPY ¥
- **Real-time Expense Tracker** (`ExpenseTracker.tsx`) — add, categorize, and track costs dynamically
- **1-click exports**: Printable PDF · Google Calendar sync · `.ics` iCal download

---

### 💾 Persistence & Authentication
- SQLite database via Prisma ORM
- JWT-based user authentication (`bcryptjs` password hashing)
- Save, retrieve, and delete itineraries via **"🧳 My Saved Trips"** modal

## 4. End-to-End User Workflow (Step-by-Step)

This is the journey a user takes from opening Xplora to having a complete trip plan in hand.

```
STEP 1 — LANDING
  User visits Xplora → sees Hero section with NLP prompt input box
  Can also click a Popular Destination card for 1-click trip generation

STEP 2 — NATURAL LANGUAGE INPUT  [Screen 1]
  User types: "5-day trip to Goa, 40k budget, 2 people, beaches"
  → POST /api/parse-query

STEP 3 — NLP PARSING & CLARIFICATION LOOP
  If all fields found → proceed to Step 4
  If fields missing → ask clarifying question → back to Step 2

STEP 4 — CONFIRM PARSED DETAILS  [Screen 2]
  ConfirmParsedDetailsModal opens
  User reviews: Destination · Dates · Duration · Budget · Interests
  User clicks "Confirm & Generate" or edits fields first

STEP 5 — ITINERARY GENERATION  [Background]
  → POST /api/generate-itinerary
  → GET  /api/weather  (live forecast check)
  → Rain check: outdoor → indoor swaps if precipitation > 50%
  → Recommendation scoring formula applied to all activities
  → Spatial nearest-neighbor clustering per day

STEP 6 — ITINERARY VIEW  [Screen 3]
  Day-by-day itinerary rendered with:
  • Activity cards with scores (e.g. 92/100)
  • WeatherSwapBanner (if any outdoor→indoor swaps happened)
  • InteractiveMap with daily GPS pin toggles
  • FlightHotelResults cards (live search results)
  • WeatherCard with current conditions

STEP 7 — FINANCIAL PLANNING
  ExpenseTracker opens → user adds costs, switches currency
  Real-time totals in selected currency

STEP 8 — EXPORT / SAVE
  • Download PDF of itinerary
  • Sync to Google Calendar (1-click)
  • Download .ics calendar file
  • Save trip to account (stored in SQLite via Prisma)

STEP 9 — AI CHAT ASSISTANT (any time)
  AIChatDrawer floating button → conversational assistant
  Remembers trip context via tripMemory state
  Accepts follow-ups like "change day 3 to heritage sites"
```

## 7. API Endpoints — What Each One Does

```
app/api/
├── parse-query/          → NLP parsing: free text → structured JSON entities
├── generate-itinerary/   → Scoring + clustering → day-by-day itinerary
├── weather/              → Live weather forecast (WeatherAPI / Open-Meteo fallback)
├── flights/              → Live/catalog flight search with filters
├── hotels/               → Hotel search with proximity and price filters
├── itineraries/          → CRUD: save, retrieve, delete user itineraries (Prisma)
├── auth/register/        → Register: hashes password, creates User record
├── auth/login/           → Login: verifies password, issues JWT token
└── chat/                 → AI chat assistant responses (AIChatDrawer backend)
```

| Endpoint | Method | Input | Output |
| :--- | :---: | :--- | :--- |
| `/api/parse-query` | `POST` | `{ prompt: string }` | `{ destination, startDate, durationDays, budget, numTravelers, interests, missingFields }` |
| `/api/generate-itinerary` | `POST` | Confirmed trip params | Day-by-day itinerary JSON with scored activities |
| `/api/weather` | `GET` | `?city=Goa&days=5` | Weather forecast array per day |
| `/api/flights` | `GET` | `?from=DEL&to=GOI&date=...` | Sorted flight options with scores |
| `/api/hotels` | `GET` | `?city=Goa&budget=...` | Sorted hotel listings with scores |
| `/api/itineraries` | `GET` | Auth header | User's saved itineraries list |
| `/api/itineraries` | `POST` | Itinerary JSON | Saves trip to SQLite |
| `/api/auth/register` | `POST` | `{ name, email, password }` | `{ token, user }` |
| `/api/auth/login` | `POST` | `{ email, password }` | `{ token, user }` |

## 8. Component Anatomy — What Each File Does

### `app/page.tsx` — The Main Application Shell
The heart of Xplora. Orchestrates all three screens, holds global state (current itinerary, parsed trip data, user session), renders the Hero NLP prompt input, popular destinations marquee, and conditionally renders Screen 2 and Screen 3 modals.

---

### `components/AIChatDrawer.tsx` — Floating AI Assistant
A slide-in chat drawer accessible from any screen. Maintains **conversational trip memory** (`tripMemory` state) so follow-up messages like *"change day 2 to heritage sites"* remain contextually aware. Budget parsing is flexible — handles both `30k` and `30000 price` formats.

---

### `components/ConfirmParsedDetailsModal.tsx` — Screen 2 Verification Modal
Displays every field the NLP parser extracted in fully editable form. Bridges user intent to the itinerary generator. Prevents "garbage in, garbage out" by letting users fix misunderstandings before generation.

---

### `components/ExpenseTracker.tsx` — Multi-Currency Finance Tracker
Live expense logging with currency conversion. Supports INR · USD · EUR · GBP · AED · JPY. Users add individual expense entries (name, amount, category) and see real-time running totals per currency. Powered by `lib/currencyUtils.ts`.

---

### `components/FlightHotelResults.tsx` — Booking Cards
Renders scored and sorted flight + hotel search results. Includes filtering UI: non-stop toggle, time-of-day slots (morning/afternoon/evening), beach-proximity filter, airport-proximity filter, star rating filter. Cards show price, score, and key attributes.

---

### `components/InteractiveMap.tsx` — GPS Route Map
Visual map component that renders GPS pins for every activity location. Users can toggle pins per day — showing only Day 1 stops, or all days at once — to visualize daily routes and geographic spread.

---

### `components/MyTripsModal.tsx` — Saved Trips Dashboard
Opens a modal listing all itineraries the user has previously saved. Each trip shows destination, dates, duration, and a delete option. Fetches from `/api/itineraries` using the user's stored JWT token.

---

### `components/WeatherCard.tsx` — Weather Info Display
Compact card showing the current weather at the destination: temperature, condition, humidity, wind speed. Used inline within Screen 3's itinerary view.

---

### `components/WeatherSwapBanner.tsx` — Rain Alert Banner
A dismissible notification banner that appears on Screen 3 when at least one outdoor activity was automatically substituted due to rain forecast. Lists which activities were swapped and what they were replaced with.

---

### `components/DarkModeToggle.tsx` — Theme Switcher
Toggle button that switches between light and dark design themes. Persists preference and applies CSS class to the root element, switching between the light (`#F4F1E6`) and dark mode color palettes.

---

### `lib/destinationsKnowledge.ts` — Destinations Knowledge Base
The largest file in the project (~40KB). A static knowledge base of destination-specific activity data, GPS coordinates, point-of-interest descriptions, and category tags used to populate itineraries when live APIs are unavailable or to supplement live data.

---

### `lib/exportUtils.ts` — Export Engine
Three export modes:
1. **PDF** — Generates a printable PDF of the full itinerary
2. **Google Calendar** — Constructs Google Calendar event URLs per activity for 1-click event creation
3. **iCal (.ics)** — Generates a standards-compliant `.ics` file downloadable directly to any calendar app

---

### `lib/weather.ts` — Weather Fetcher with Fallback
Fetches forecasts from **WeatherAPI** (requires API key). If unavailable or the call fails, automatically falls back to **Open-Meteo** (fully keyless). Ensures the weather feature always works even without a paid API key.

---

### `lib/currencyUtils.ts` — Currency Conversion Math
Maintains exchange rate constants and provides conversion utility functions. Supports 6 currencies.

---

### `prisma/schema.prisma` — Database Schema

## 9. Core Algorithms Explained

### Algorithm 1 — NLP Entity Extraction (`/api/parse-query`)

**Input:** Free-text string from user  
**Process:**
1. Regex + keyword matching to detect destination names, date patterns, duration words (`5-day`, `week`), budget formats (`40k`, `40000`), traveler counts, and interest keywords
2. Validate extracted values (date must be in future, budget must be positive, destination must be resolvable)
3. Identify `missingFields` array

**Output:** Structured JSON or targeted clarifying question for first missing field

---

### Algorithm 2 — Recommendation Scoring (`/api/generate-itinerary`)

```
Score = 0.4 × Rating  +  0.3 × PriceFit  +  0.3 × InterestMatch

Where:
  Rating       = normalized(starRating or reviewScore) to [0, 1] scale × 100
  PriceFit     = 1 - |actualCost - idealCost| / idealCost   (clamped to [0, 1])
  InterestMatch = fraction of user's interests matched by the activity's tags
```

All three components are normalized to 0–100 before the weighted average. Activities below a threshold are filtered out. Results are sorted descending so best options surface first.

---

### Algorithm 3 — Spatial Nearest-Neighbor Clustering

**Input:** List of candidate activities with `(lat, lng)` coordinates  
**Process:**
1. Start from the hotel/accommodation GPS coordinate as "current location"
2. Calculate Haversine distance from current location to all remaining unscheduled activities
3. Pick the nearest activity as the next stop
4. Update current location → repeat until the day's time budget is exhausted
5. Repeat for each day independently

**Goal:** Minimize total commute distance per day, producing logical walking/driving routes.

---

### Algorithm 4 — Weather-Swap Logic

```
For each day in itinerary:
  fetch weather forecast for that date + destination
  if precipitationProbability > 0.50:
    for each activity in day:
      if activity.category in [BEACH, OUTDOOR, HIKING, NATURE]:
        swap activity with nearest indoor alternative from same destination
        set activity.isIndoorSwap = true
```

Indoor alternatives are drawn from the `destinationsKnowledge.ts` knowledge base filtered by `category: INDOOR`.
